# Composed durable population creation — staging only

This composes the frozen `private-creation-fixture`, `population-creation-wiring` and `population-creation-binding-v2` increments in a new folder. Their old files remain unchanged. No production source, installed pack, world, UI, timer or deployment was changed. The actual compiled trust descriptor remains **literal null**. Synthetic trust exists only behind the isolated Node test loader. This is not a production activation receipt or native acceptance.

## Runtime behavior

The lazy runtime uses **only the private adapter's store**. Construction and the one death subscription registration remain free of native reads. Before returning any store, falling back to legacy streets behavior, explicitly initializing legacy history or processing a death callback, it checks activation status. Intent-only, unknown-family/schema, unconfigured receipts and fresh core headers without matching completed activation HOLD. A second status/census check catches changes during selection. Legacy initialization repeats this check after its kingdom eligibility getter. No activation intent/header is cleared or automatically rescued.

An unconfigured/null descriptor with no history retains the existing legacy default. A privately configured descriptor with neither activation nor core history HOLDs before default births, including when its initial-spawn attempt fails. Existing explicit legacy core epochs retain their deliberate preservation path; legacy mode cannot refill unseen unknown groups. There is no second owner, spawner or casualty counter. Normal hour reconciliation and gate-off teardown use the same existing owner and its positive removal receipts. The existing single death subscription calls the same durable store; unload/entityRemove never substitutes for a death.

`civ:people creation fresh confirm` passes the actual event source entity into the private adapter. Console/absent/wrong-dimension callers and public receipt/epoch/fresh arguments cannot authorize fresh creation. All exact initial-property, control, marker and bounded census checks remain in the unchanged private adapter. The core and private adapter bytes match the reviewed source stages exactly; the owner is the wiring-stage extension of the v2 owner, including its bound teardown.

Completed **runtime status revalidates durable activation receipt and core registry/epoch**, not the one-time vanilla marker or activation caller. Later ordinary play, player departure, people-on, developer-off or scoreboard edits do not revoke existing actors. The earlier private adapter README's recurring-marker promise is superseded by this settled contract. Corrupt/partial durable state still holds. Native multi-property atomicity and arbitrary last-getter adversarial atomicity are not claimed.

## First-spawn boundary and actual preparation gate

The existing welcome subscription now invokes a private runtime hook synchronously **after** `ensureInitial()` and before the welcome message. No subscription or timer is added. With null trust, this hook performs zero native reads. With compiled trust, activation additionally requires a preexisting developer flag, people strictly off, no active job, the exact initial kingdom and authentic marker. It never sets a developer flag and never accepts evolved kingdom state. A missed/failed hook in a configured build holds later streets births instead of silently using legacy behavior.

A genuine vanilla marker source has no main-pack developer flag. Therefore this hook does **not** eliminate the operator preparation gate: preserve the pristine closed vanilla source and its receipt forever; on a disposable derivative bind the same main BP, set its existing `civ:generate_devgate on` development switch, then either explicitly activate or save/close while the kingdom is still exactly step 0 and relaunch for the private hook. Root must witness/pin that preparation chain and actual marker/source receipt. If the first accepted hour has elapsed, refuse and restart from a new pristine clone; no reset, rewind or retrospective blessing is provided. Native preparation timing and the hook's actual Minecraft acceptance remain unverified. A future authenticated pre-hour preparation route would require its own review.

## Starter/export

The whole `civ:creation_activation:` family and whole `civ:pop_bind:` family are kept even against broad wipe rules. Starter arming and the existing export readiness path both use `starterArmProblems` and refuse either family. Nothing discards intent, unknown schema or inventory records. This prevents the in-game supported export path; an external operator who bypasses/stales its receipt is outside runtime proof.
