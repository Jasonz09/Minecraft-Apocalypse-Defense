## Filesystem and failure rules

The path/UUID/hash/no-link/retained-backup approach follows existing `dev/deploy.mjs`; that CLI cannot be imported without executing it, so this narrow helper reuses its rules rather than altering the release deployer. It additionally checks bounded descriptor reads and growth, exact pinned private bundle plans, case-insensitive duplicate UUIDs in normal Shared/user scan parents, absolute contained paths, disjoint source/target/backup roots, same target/backup volume, empty new transaction/world paths and a recognized complete prior pair (or both absent).

Both packs and the world clone are copied and hash-verified outside all scanned pack/world parents before any installed pack moves. Both previous packs are moved to retained backups before either new pack is installed. Each rename repeats containment, no-overwrite, closed-game and exact source-hash checks after the test fault seam. Append-only receipts record stages. Nothing is recursively deleted or overwritten by the helper.

On an ordinary failure while the game remains closed, any installed new pack is retained outside scan roots, and verified copies of the prior pair are restored. The original previous backups remain outside scanned roots even after rollback. The world is published last; a failed published clone is retained outside the catalog. Unknown/concurrently edited destinations are never overwritten to force rollback. If Minecraft opens or safe rollback is blocked, the helper stops, retains all available original/new bytes and records `manualRecovery:true`; it cannot promise multi-directory atomicity or move live files safely. Root must close the game and inspect the receipt before recovery. Existing transaction/world targets always refuse; no automatic pending recovery or epoch reuse occurs.

## Explicit naming scope

The source is the pinned private fixture's staged derivative, whose only differences from the immutable pristine source are its two binding lists. This helper changes only **levelname.txt** and the real **LevelName** string in level.dat (plus its required payload-length header). A bounded full typed NBT walk validates all tags, depths, lengths, duplicate keys and exact end, then patches that one actual string span. The existing independent level.dat reader fully reparses before/after; every other semantic value, root name and version must compare exactly, including BigInts. The exact new nine-file world inventory is in the plan before copying. The DB, level.dat_old, icon and other files remain byte-identical. Total scope versus pristine is therefore the two bindings plus the two explicit naming files; no DB mutation is performed.
