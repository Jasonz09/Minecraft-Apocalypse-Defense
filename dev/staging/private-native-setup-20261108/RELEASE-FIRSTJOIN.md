# Required release first-join path — design gate, not implemented authority

The current private fixture proves one developer source at exact initial state. It cannot authorize a finished city's release template. Null production trust still uses legacy population behavior, and starter arming currently refuses creation history. Neither limitation may be bypassed by clearing history, accepting `fresh=true`, checking only a loaded census or resetting a played city.

The concrete next release slice should reuse the existing store, one owner, durable intent/header/complete protocol and welcome hook:

1. Prepare a **separate** never-population-enabled completed city source. Preserve its closed source and all history. Pass the existing clean-starter/release gates, including all five districts, saved plans/queues and retained maintenance receipts. A merely empty cursor/entity list is insufficient.
2. Produce a genuine immutable clean-template receipt tied to the approved template/archive SHA, BP/RP identity, exact armed `buildStarterBaseline` bytes, all saved-city sources and explicit never-issued population inventory. Audit closed storage/entity history with its coverage limits; require the witnessed preparation chain. If existing history cannot be reconciled without losing issued actors, this source cannot become the release template.
3. Add a separately reviewed **clean-starter** trust profile to the existing activation adapter. Its only acceptable pre-activation state is that exact approved armed baseline and marker/receipt, not the private virgin kingdom. No public command arguments supply freshness. Any played/evolved/missing/partial/unknown state holds.
4. On the clone's first welcome, after seeding/loading but before an owner hour, use this trusted profile to publish durable activation intent, the exact fresh registry header and completion. An epoch belongs to that clone's durable activation; its exact native identity/minting mechanism must be reviewed and fault-tested before coding. This work must not introduce another timer or actor owner. Pending activation holds across restart and never defaults to legacy births.
5. Keep all later births/unload/gate-off/deaths through the same owner/store. Test independent new-template clones, first join, rejoin, all write crashes, unloaded survivors and copied/foreign/missing source refusal. Native clone provenance cannot be inferred from an arbitrary player-supplied marker. Explicit legacy worlds retain their preservation path and require a separate migration policy.

Starter arming/export and first-join ownership therefore need a reviewed **never-issued clean-starter profile**, not a blanket removal of today's history refusal. Implementation should change that exact transition only after the private native protocol and genuine finished-city release receipt exist. The current release checker remains authoritative; this note grants no release approval, general freshness claim or feature-complete status.
