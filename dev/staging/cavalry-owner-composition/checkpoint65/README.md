## Implemented

The fresh schema3 binding registry stores single actors and compound rider/mount records in one exact bounded issuance inventory. This is independent of kingdom schema3. The facade delegates existing v2 worlds to the unchanged byte-pinned archer/creation core. It performs no migration or header reinterpretation. Missing issued records, mixed/future namespaces, copied tickets, reused actor IDs and uncertain outcomes hold. Each pair role has its own generation-bound identity and positive removal/death record; a horse never debits soldiers. No human casualty debit is introduced either.

Optional physical cost2 flows through the actual reducer and LOD algorithms and selected schema3 cavalry codec. Both district8 and global24 admission caps remain unchanged. Default groups retain cost1 and their previous report shape. Schema1 swordsman/schema2 archer selection behavior is retained. There is no new public cavalry command or fixed class mix.

The EXISTING population owner now plans bounded pair maintenance. Known-never parts can be cancelled; alive/removing parts require exact positively proven removal. Pending/unloaded/foreign/ambiguous parts hold. A half-created pair can remove its one known actor and cancel only the uncreated counterpart. Rider/mount relationship queries reject foreign passengers or inconsistent seating. No eject, mount teleport, actor adoption or namespace-only deletion occurs.

Role actions share the existing spawn/action counters. Before any native maintenance, the owner CAS-publishes and reads back the complete planned tick quota. An after-write crash preserves spent quota; same-tick restart cannot gain another removal. Issued pairs require a valid existing owner cursor, so corrupt/absent cursor cannot reset their quotas. Terminal-save failure leaves removing/unknown tracked rather than inferring death from absence. A final `saved:false` can therefore coexist with a successfully prepaid cursor reservation; the report explicitly labels `quotaPrepaid`.

Gate-off cleanup uses this SAME owner method and existing streets lifecycle, now passing its existing owner tick. With one available action, cleanup removes one role, preserves the other, and completes only on a later tick with budget. No second timer, companion spawner or owner exists. All binding metadata and selected-policy checks precede final fresh native identity/type/tag/location/loaded proofs; block-getter retag/unload regressions hold before deletion.

Dry-run output contains detached role jobs and holds, not executable tickets. Unresolved pair cleanup conservatively defers ordinary births; this is a safety hold, not complete component-reservation admission accounting. The ordinary single-owner path remains functional, including exact v2/v3 birth-tag removal compatibility.

## Pending-component capacity and per-role completion increment

Before ordinary admission, the actual owner derives reservations from the verified binding registry and passes them through reducer/LOD. Each unresolved pair reserves two slots even when one/both actors are unloaded, outside the observation/group table, pending or removing. Fully terminal/cancelled pairs release their reservation. Own admitted pairs are not double charged. Reservations consume district/global limits before another group is admitted; physical admission counts remain separate from reserved/charged slots. A bound class/cost mismatch refuses. This keeps unseen surviving components from donating slots to new actors.

`compoundPlanning.js` schedules at most one explicit role per pair per pass and charges a hypothetical shared op+spawn budget. ## Exact remaining gates

**Native compound birth and seating are disabled before any spawn or role intent.** Cleanup is useful for positively tracked existing pair records, but this proposal alone cannot make a cavalryman. Before enabling births, connect the metadata-only per-role protocol to reviewed native two-body clearance, role-aware positive event routing and recovery, and reviewed horse/rider data. Then prove seating, mounted collision, movement, combat, gate-off and unload/rejoin natively. Missing actor alone never authorizes replacement.

The production private fresh adapter currently proves exact v2 header and null trust. It must not initialize this v3 store accidentally. Default facade format remains2; a future reviewed trusted fresh-v3 adapter and explicit transactional v2 migration are missing. Legacy worlds are preserved rather than silently reset. New injected modules also require explicit central architecture-boundary allowlisting with inverse engine-import checks before integration. No production promotion is requested at this checkpoint.
