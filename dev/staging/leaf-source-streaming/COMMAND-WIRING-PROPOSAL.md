# Eventual command integration — review proposal, not integrated

The staged pending and fresh compilers are read-only. Private prepared-batch functions and exact controller/command patch artifacts are now authored, but the patch hunks have not been applied or executed even in an isolated copy. They are not currently a production command or population/build owner. The existing wrapper gates and controller journal/commit rules remain authoritative. An arbitrary caller-provided `LeafPlan` cannot replace those rules.

Retain these existing `repairSavedWallLeaves` checks unchanged: completed Overworld selected district and player; sole `civ-wall-leaf-repair` reserved job; player validity/dimension/token cancellation; raw source guard captured before loading; 1–5 exact unique supported completed district identities in the same dimension; orphan original `civ:jobs[:dN]:meta` rejection; original master and dimension equality; original queue state/spec/checksum validation; all-source protection geometry; exact policy; pre-resolved native masonry permutations; no lease/chunk loading.

The controller should still perform its current bounded journal census first: unknown versions/keys, >80 total histories, >16 per district and multiple unfinished batches refuse with every receipt retained. Its exact expected leaf-receipt key/raw-value map must wrap `sourcesCurrent` before any source loading. Capture a metadata-only expected source manifest only after the command's existing kingdom/orphan-key gates. Do not discard an unreadable/incomplete/aborted source to get a smaller source set.

The authored **module-private prepared-batch capability** is separate from both the preview census token and wanted-cell accumulator token. Its producer brands only after one of the staged fully guarded source compilers has finished. It stores only immutable final plan/survey data, a scalar identity string, existing receipt raw stamp where applicable and the exact guarded-reader function reference. It stores no records, wrappers, ops generators or ground. The proposed controller consumes it once, requires the identical guarded-reader capability/current source identity, and checks the existing pending-receipt CAS again. A plain object, partial census, partial accumulator or parsed plan cannot enter prepare/commit. These functions and unapplied patch hunks still require isolated tests/typechecking before command promotion.

For an unfinished receipt, the callback receives the controller-owned `storeFor(originalJournalKey)` reader and compiles the original admitted coordinates using the staged pending path. Existing receipt binding/digests, strict preview, prepare, idempotence and WAIT commit remain unchanged. For fresh admission, the callback runs the staged fresh path, preserving the whole selected-wall census and all-source classification. A truncated survey returns a held result and never a partial batch. A no-eligible result preserves its full incomplete/refused survey. Only a nonempty strict final plan receives the same computed journal key and existing retained-capacity checks; its immutable capability then enters ordinary admission.

The source loader callback can call the existing `loadSavedRunSteps` directly inside this same cooperative job. It must still verify the complete original queue and source checksum; callbacks are not a replacement for those checks. After the first successful verified load, a synchronous `onVerifiedMaster(plan)` callback may compute the existing small protected rectangles before any live census reads. The callback must not retain the heavy wrapper/record. Every later source must have exactly the same serialized master plan. The native `isProtected` reader must return unknown/refusal until this geometry has been initialized; it must never default to permissive false. The first selected source is loaded first for fresh census, while all other expected sources still finish verification before classification/admission.

The native adapter and `readTick:()=>system.currentTick` remain identical. Keep all <=56-read commit/full-state/CAS/final-handle/final-neighbor barriers, exact-original-state WAIT semantics, readback/checkpoint faults, cancellation and retained receipts. No new policy/schema/dynamic-property namespace or timer is needed.

Before promotion, run the authored real-source parity checks and add an actual command-boundary test proving: orphan jobs still reject; invalid master/dimension/queue still reject; every expected source is visited; `isProtected` remains fail-closed until the verified master callback; source/receipt/cancellation changes bracket all yields; plain/partial capabilities reject before any setter; no eligible or truncated/incomplete surveys keep truthful counts; and original pending `c835b06e` retains schema2 identity. A native memory/stability claim requires separate installed Minecraft checks.
