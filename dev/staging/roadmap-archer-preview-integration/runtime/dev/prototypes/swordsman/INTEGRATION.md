# Swordsman integration design

**Design only, November 5, 2026.** The prototype assets and resolver remain isolated. Implement the first class through the existing owner on a fresh trial copy, with one explicitly selected soldier group and no automatic replacement or fixed class mix. Complete native appearance/targeting/pursuit acceptance before enabling authoritative casualties.

## Current production boundaries

All paths below are relative to `CivilizationApocalypse_BP/scripts/`.

| Boundary | Current behavior | Minimal extension |
|---|---|---|
| `population/groups.js`: `buildGroupTable`, `groupIdOf`, `parseGroupId` | Derives stable **rank-slot** IDs from aggregate counts; soldier group size is normally five, final group can be partial. | Keep canonical ID parsing and current counts for the appearance trial. Do not reinterpret a slot as a durable named cohort. |
| `population/settings.js`: `POP_ENTITY_TYPES` | One default type per kind: villager and iron golem. | Preserve defaults. Add an injected pure, per-group resolver rather than replacing the global soldier type. |
| `population/reconcile.js`: `indexEntities`, `keepRepresentative`, admitted spawn branch | Spawn action uses `POP_ENTITY_TYPES[detail.kind]`; identity/duplicate handling uses tags and currently drops observed `typeId` from indexed entries. | Resolve expected type for every group; refuse type conflicts **before any destructive actions**, including duplicate cleanup. A live golem/custom conflict must not become automatic conversion. Charge new work to existing budgets. |
| `integration/popSync.js`: `describe`, `plan`, `planFromStore`, `spawnOne`, `reconcileOnce` | Reads observed type; plans through the pure reducer; performs dimension-wide tag checks before spawn; applies actions, then saves the advisory cursor. | Load one validated selection snapshot per pass; use the same resolver in planning and fresh apply-time type checks. Preserve existing safe-ground, tag and budget guards. An unreadable census must refuse the trial rather than mean empty. |
| `integration/peopleStreets.js`: `onHour`, `physicalGroups`, naming/teardown census | Constructs the sole population adapter, exposes admitted groups, names by identity and tears down owned entities. | Pass the validated resolver into its existing adapter. Keep creation/removal here; naming/status/teardown remain tag-based and class-aware. No swordsman driver that spawns entities. |
| `integration/peopleOrders.js`: `LEVY_TYPE`, `levyOf`, `postDistrict` | Accepts only iron golems, then assigns posts using teleport and facing. | Match exact expected type **after** canonical identity and admission checks. For the initial home-restricted guard, report a separate stationary trial role and exclude it from teleport/post allocation. |
| `main.js`, `integration/peopleRuntime.js` | Streets → siege → Orders after the simulation saves; drivers receive the saved kingdom and must not write independent population changes. | Share one selection-provider boundary. Maintain early-execution safety, idempotent registration and current owner order. No new periodic entity spawner. |

## First implementation: durable selection and owner wiring

1. Add a small pure selection codec and injected runtime store, for example `population/militarySelection.js` and `integration/militarySelectionStore.js`. Proposed payload: `{v:1, trialId, groupId, class:"swordsman", typeId:"civ_trial:swordsman", dimension:"minecraft:overworld"}`; bound it to one selection and a small byte ceiling. These are proposed new fields, not current saved state. Absence means disabled; corrupt/newer/unreadable data means refuse trial operations, never silently use the golem default for an existing selected actor. Freeze/copy decoded data for the duration of a reconcile pass.
2. Add an explicit development command for preview/confirm/status. Confirm requires the people gate off, no construction/maintenance, a compatible saved kingdom, one existing derived `sol` group and a **fresh trial provenance check plus successful owner census**. Reject any already admitted/canonically tagged representative for the selected group. A loaded-entity search alone does not prove an arbitrary old world's unloaded chunks contain no prior actor; activation is restricted to a separate known fresh fixture/copy before normal promotion. No automatic golem replacement, no “convert all soldiers”.
3. Persist and read back the selection before allowing normal promotion. On failed write/readback, keep the trial off and surface the refusal. Selection survives people-off teardown and rejoin; clearing it is a separate guarded action that requires no surviving selected actor and no pending binding/death receipt. Never erase the selection merely because its actor is out of view. If the selected group no longer exists after ordinary count changes, hold/report the selection instead of assigning the class to a different index.
4. Thread an optional resolver through `createPeopleStreets` → `createPopSync` → `reconcile`. Pass the actual derived group record to it. The existing spawn action still carries the resolved `typeId`; only `spawnOne` calls `dimension.spawnEntity`. At apply time re-read selection identity/version and any canonical representative; a changed selection, wrong type, duplicate or unreadable query defers/refuses. Do not interpret `findTagged`'s current exception-to-empty fallback as successful activation/type validation.
5. Preserve the canonical `civpop:v1:<groupId>` tag, ordinary cursor, caps, LOD and safe standing probe. The advisory `civ_pop` cursor must not contain authoritative class selection, birth receipts or casualties: corrupt cursor recovery intentionally reconstructs an empty cursor. Compare observed and expected types for the selected group; a mismatch blocks selected-group writes and prevents its conflicting actors from entering generic duplicate removal. Conservative first implementation may refuse that entire pass.
6. Wire the same selection into Orders. `levyOf` must require an unambiguous canonical soldier claim, membership in streets' admitted set and the exact resolved type. Recognize the swordsman for status/naming, but route it out before front-share/post/officer allocations, so a skipped actor does not consume a golem post slot or acquire a misleading officer title. Report the stationary trial separately. Its spawn-centered `minecraft:home` must not silently conflict with hourly teleporting. Moving home/posts is later work requiring an explicitly supported API/event design and native rejoin checks.
7. Add the entity data module and matching RP through a reviewed packaging change; retain all existing script modules and dependencies. Make template/development residue handling explicit in `sim/starter.js` (`classifyStarterKeys`/`describeStarterState`), `commands/starter.js` and starter tests. Pending trial selection/bindings/receipts must block release export until deliberately reconciled; do not casually wipe authoritative receipts during arming.

The first native trial is appearance and bounded combat behavior only. No economic resource debit, casualty debit or changed soldier headcount is included. Keep it nonlethal or stop before a guard death; if a representative dies under today's owner, it can later respawn from unchanged aggregate counts, so that run is not casualty acceptance.

## Casualty authority: required decisions before implementation

`sim/war.js:resolveAssault` currently subtracts `defenderLosses` from `district.soldiers`; the withdrawal path also subtracts losses, and `assignDefenders` maintains front/reserve totals. `sim/tick.js:advanceKingdomStep` runs war before evacuation/construction/expansion/population/training and rolls back a rejected step. `integration/simulationLoop.js` saves the accepted kingdom **before** calling people drivers. A death observer cannot independently subtract soldiers inside a post-save driver without creating a second authority and overwrite/replay risks.

**Two gameplay decisions are still open:** what a representative death means for its represented people, and whether physical combat replaces or merely visualizes simulated defender losses during an explicitly identified engagement. Do not silently choose one-person or five-person debit, or add observed deaths on top of the same simulated loss.

There is a structural blocker beyond deduplication: current groups are rank slots. With 30 soldiers, killing `sol:0` and subtracting five yields slots `sol:0..4`; normal reconciliation recreates `sol:0` while retiring the unrelated `sol:5`. A tombstone on `sol:0` alone loses the intended representation/capacity relationship. Reusing that slot for reinforcements also makes an old delayed death unsafe. Broader authoritative physical casualties need a reviewed **durable cohort/generation membership model** whose survivor accounting derives the aggregate, or another explicit policy that reconciles slots and survivors. Do not pretend the existing tag solves that problem.

The smallest casualty proof fixture can contain one group in an isolated district with explicitly agreed headcount semantics and no recruitment/training/expansion during the test. That avoids slot-shrink ambiguity while proving receipts; it does not authorize that policy for the full kingdom or select a military class mix.

## Proposed receipt/commit boundary after those decisions

- Add a bounded authoritative binding record with `trialId`, group/cohort ID, monotonic birth generation, entity ID as an **opaque string**, type, dimension and represented-headcount policy/snapshot. A generation must change on a genuine new birth. Snapshot headcount cannot be trusted forever if population/war/training can resize the group; reconcile or invalidate the binding at the same population transition before accepting a later death.
- Subscribe once to stable 2.7 `world.afterEvents.entityDie` (local declarations expose `deadEntity` and `damageSource`). Capture only an exactly admitted, bound trial generation. Read tags/ID defensively; a dead handle may be unreadable. Unknown, conflicting or stale generations are diagnostic refusals, not inferred casualties. `remove()` for LOD/teardown/rollback is not a combat death; keep owner retirement intent distinct and verify actual event behavior natively.
- The event handler writes only a bounded durable inbox receipt `{receiptId, trialId, cohort/group, birthGeneration, entityId, representedHeadcount, engagementId, cause}`; it does not save a second kingdom snapshot or mutate soldiers. Use generation plus identity for deduplication, not resettable game tick alone. On storage failure/overflow, hold trial respawn/accounting and surface the failure; never discard an unread receipt to make room.
- One kingdom transaction applies each eligible receipt at a documented point in `advanceKingdomStep` and writes its consumed ID/sequence **inside the same serialized kingdom value as the casualty effect**. Validate garrison totals via existing rules and run `assignDefenders` as appropriate. This is a logical single-save commit, not a promise of disk-level atomic durability. A separate inbox cleanup happens only after that commit is observed. `kingdom/store.js:save` currently provides schema-version protection, not compare-and-swap or a general multi-key transaction; keep one sequential writer and do not yield between snapshot validation and save.
- Supply an explicit per-engagement authority policy to `resolveAssault` and withdrawal handling: existing simulation mode remains default; a future physical-authority mode must exclude the same covered cohort losses from simulated deduction. Mixed loaded/unloaded cohorts cannot be globally exempted without matching coverage records. Receipt ingestion belongs before the chosen simulation calculation, not in the post-save streets callback.
- Retain monotonic generation/consumption watermarks or closed-engagement tombstones so bounded compaction cannot make a delayed old event charge a new birth. Selection/binding/inbox version and capacity errors fail closed. No claimed “exactly once” until replay, authority transitions and roster changes are tested together.

## Crash/rejoin limits that acceptance must expose

| Interruption | Intended recovery | Remaining limit |
|---|---|---|
| Selection saved, actor not spawned | Normal owner retries with that saved resolver. | Unknown/missing asset pack must refuse; do not fall back to golem. |
| Actor canonically tagged, advisory cursor not saved | Existing tag census adopts it with matching saved type/selection. | Current spawn→tag sequence has a crash window leaving an untagged entity; the prototype does not solve it. Fresh native adoption checks are required. |
| Actor spawned/tagged but future generation binding unfinished | Hold activation and reconcile a prepared birth record against exact identity/generation; never blindly mint another actor. | Entity, property and cursor writes are separate engine operations. A birth journal needs its own crash tests and cannot make an unobserved untagged stray provably attributable. |
| Chunk unload, invalid handle or absent census entry | Wait; no receipt, debit or death inference. | Dimension-wide queries see loaded actors, not a durable proof of nonexistence in unloaded chunks. |
| Death occurs before receipt is durably captured | Report uncertainty; do not invent or duplicate a debit. | No proof that native death events replay after process failure; total lossless death capture is **not guaranteed** by Script API events. |
| Receipt saved, kingdom not committed | Hold replacement; replay receipt once through the transaction. | Must validate birth/cohort/authority, not just the same reused rank slot. |
| Kingdom debit+consumption committed, inbox cleanup interrupted | Skip consumed receipt on replay; clean up afterward. | Two-key cleanup is not atomic; bounded retention rules must preserve deduplication. |
| A simulation step rejects or its save fails | Do not consume receipts or release their replacement hold. | Physical world damage may already have happened and is not rolled back with the pure simulation. |

## Acceptance gates in implementation order

1. **Selection/owner tests:** off-default parity, one selected real group, missing/newer/corrupt store refusal, activation census failures, wrong-type/duplicate protection, apply-time selection changes, asset-unavailable failure, crash after tag before cursor save and rejoin adoption. No extra creation/removal path or changed population budget.
2. **Orders tests:** selected actor recognized but never teleported, golem post allocations preserved, class does not become an accidental commander, unloaded/unadmitted/ambiguous actors ignored, normal gate-off teardown still owns removal.
3. **Native appearance/combat test:** accepted content log; visibly human guard and modeled sword; friendly exclusion including accidental hits; exact managed-zombie eligibility, observed one-second cooldown, pursuit/home behavior, blocked-path/water/knockback cases; stable identity and exactly one actor through unload/save/rejoin. These are not currently proven by the offline asset checks.
4. **Separate casualty design acceptance:** choose headcount and engagement authority; resolve rank-slot/cohort semantics, then implement and test durable bindings/receipts. Test partial groups, stale generations, duplicate events, storage failure, rejected hour, save failure, crash/replay windows, simulation/physical handoff, withdrawal, training and reinforcement. Start with the isolated single-group fixture; broaden only after survivor membership stays correct.

No active production files or existing tests are changed by this design.
