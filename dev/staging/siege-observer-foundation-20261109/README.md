# Siege read-only observer foundation — NOT configured/native

Original1DE6, correctedBE59 and all independent failures are untouched. This NEW stage owns a bounded correction and a read-only candidate adapter, not combat resolution or production wiring.

S5 is a meaningful injected-port reentrancy failure: the last CAS getter returned old bytes while replacing the same key. A bounded fresh raw reread after validated load, recensus and another final raw comparison catches that exact trace before writing. Native Script API has NO atomic CAS. The final getter/setter and distinct hostile world wrappers remain a trusted native-port boundary; this code does not claim arbitrary-host linearizability or infinite protection against callbacks scheduled at whichever getter is last. The module-level same-canonical-world reentry guard remains.

Journal `lookupActor` is read only and returns a detached frozen record plus bounded source bytes for comparison. Source bytes are NOT a native permission ticket. It retains full current validation/caps. Existing born/death/remove primitive calls still require privileged genuine native provenance; pure tests do not create it.

`createSiegeDeathObserver` defaults NULL, performs no construction-time reads, and only reads a repeated exact event handle frame, actual issued record and step. Missing records are ignored: tags or a loaded census never adopt history. It retains the original persisted wave across rollover/restart, rejects changed identity/journal, and returns an in-memory frozen CANDIDATE. It does NOT publish death, alter a journal, spawn/remove/retag/teleport, debit aggregates/resources or grant replacements. An unreadable deadEntity yields HOLD. Whether the real engine exposes a readable repeated deadEntity frame remains a native acceptance gate.

`wrapExistingDeathCallback` plus `existingDeathFilter` are proposed insertion helpers for the ONE existing creationRuntime.entityDie.subscribe call. NULL returns the exact original callback/filter, with zero extra reads. Configured wrapper runs the independent observer before the existing body (which can return early when population bindings are absent), and always invokes that existing body despite observer failures. This stage does NOT edit creationRuntime or main and creates NO subscription/timer/owner. Integration still needs default parity + actual same-subscription callback tests before promotion.

Native birth hooks remain unimplemented, so unseeded journals observe no actors; this is intentional, not complete siege coverage. Before a later writer hook: genuine exact spawn-success registration from the existing owner, source barriers, starter/export preservation/refusal for ALL encounter family versions, crash/rejoin and native event readability. Lifetime24actor/8wave caps can exhaust; no history pruning/reset fallback. Positive physical death is not cause-of-combat, winner, breach or human casualty authority.
