Instantiate one read-only observer for the existing journal, default NULL; no world reads during construction. Its birth journal must first be backed by a separately reviewed existing-siege-owner spawn-success hook. Primitive test births are not native provenance.

In `creationRuntime.registerDeaths`, retain the exact current population callback body and its current filter. Replace only the callback argument with `wrapExistingDeathCallback(originalCallback, siegeObserver)` and the filter argument with `existingDeathFilter(originalFilter, siegeObserver)`. The SINGLE existing `entityDie.subscribe` remains the sole subscription. Configured observation executes before `activeStore()`/unrelated population early returns, and its errors cannot skip ordinary population handling. NULL helpers return the exact original callback/filter. No second subscription, event polling, population mode requirement or timer.

Keep the observer's status separate from the existing creation last-signal field. Do not append unconfigured status lines or alter population result/exception behavior. A candidate currently has NO persistence sink: wiring it to `journal.death` would be a separate authority change requiring repeated native-frame/source guards, actual death-event readability proof and publication fault tests. There is deliberately no native birth, owner-remove hook or terminal journal writer in this proposal.
