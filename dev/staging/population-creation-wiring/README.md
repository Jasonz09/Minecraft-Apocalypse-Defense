# Creation binding runtime wiring — separate staged increment

This authoring proposal is separate from the frozen schema-2 core and is not integrated. It contains a lazy runtime, exact proposed main/streets/people-command/starter copies and a focused runtime test. The proposed tree now includes integration/creationRuntime.js and its exact schema-2 creationBindings.js dependency; runtime.mjs is only a test re-export. No other timer, owner, spawner or casualty debit is added.

The existing streets factory injects the optional binding dependency into the same hourly popSync. A namespace of any schema activates strict refusal rather than falling back to legacy birth. One early-safe entityDie subscription reads nothing during registration and records only exact current physical identity; missing actor/unload/entityRemove is never a death receipt. A new development command would be `civ:people creation status` or `civ:people creation legacy confirm epoch=<unique-id>`. All existing commands retain their paths.

Starter key classification keeps the entire family and starter arming/export-readiness refuses it. The external build-template pipeline relies on in-game starter verification and a human receipt; it does not independently decode arbitrary LevelDB properties. A dishonest/stale export receipt remains outside this proposal's proof.

## Required gates before promotion

* Fresh activation intentionally refuses. Current starter_arm resets aggregate state and wipes development keys; neither it, an absent cursor nor a loaded census proves there are no unloaded canonical actors. The played Pillager/Vindicator fixtures are not blank sources.
* Root must prepare a new disposable **never-people-on** world from a known clean baseline (or genuinely new world with this owner disabled), save/close it, record complete source SHA and CRC-WAL owner/binding/key history, and pin a unique receipt. The engine cannot hash its own closed LevelDB. A private compiled fixture adapter can then bind that operator-attested fixture receipt to exact saved source/property snapshots, fixed dimension and no owner history, with loaded canonical census only an additional check. No public fresh=true boolean or generic parsed request grants authority.
* A new release template needs creation initialization in its authenticated never-started preparation path, before the first owner birth, so clean new players remain able to materialize never-issued groups. Initializing a played world as fresh is prohibited. Native first birth, unload/rejoin, explicit LOD removal and crash/recovery tests are required.
* Gate-off teardown now calls the SAME popSync owner through teardownBound; strict identity/uniqueness/binding preflight happens before any removal. The existing removeOne path records intent, performs live policy and final native identity/loading checks, then requires positive exact removal before terminal publication. Legacy/foreign/duplicate actors refuse; unloaded actors are untouched; failed terminal persistence holds across rejoin. No cursor reset or birth is performed. Both near/far and gate-off paths share this protocol.
* Main/command/streets/starter copies remain staged. Composed strict TypeScript passes, and 12 focused runtime/actual-owner/staged-streets tests pass (250.916 ms). No native acceptance/full verification is claimed. Fresh activation remains an explicit missing dependency, so this is not ready for production promotion.

## Root-prepared blank fixture: concrete next native gate

1. Create a new disposable Minecraft world with the reviewed BP/RP and population gate never enabled. Do not use any played guard/combat world or arm an old authoring city as a freshness shortcut.
2. On that explicit new-world UI session, verify the development command is available, people remain off, no population cursor/military/binding history exists, and exact loaded canonical census is empty. This census supplements the operator-known new world; it does not establish arbitrary unloaded-world absence.
3. Add a unique fixture marker through a reviewed development-only preparation path before any owner birth, save and fully close Minecraft. Root records all actual files and SHA, marker raw text, kingdom/schema keys and CRC-WAL owner history. Preserve this source forever, and create only new disposable clones from it.
4. Compile one private fixture adapter against that exact receipt/marker identity. It checks the marker, dimension, no owner cursor/gate/military/binding history, no active construction/starter state, bounded strict canonical census and unchanged raw snapshots before/after its synchronous check. Only that adapter can construct the core verifyFreshWorld result; public command data cannot supply verified/fresh booleans. Runtime cannot independently hash closed LevelDB, so the receipt-to-open-world binding retains explicit operator provenance.
5. Initialize durable fresh metadata before first people-on, then test the normal sole owner's birth, canonical/birth-token identity, unload/rejoin preservation and gate-off positive terminal receipt. Save/close and verify exact binding inventory/record persistence. A crash between activation and epoch initialization must hold, never silently revert to legacy default.
6. Reopen near/far and verify new generation only after a positive owner-remove receipt. Separately test degraded death metadata and pending-birth crashes. Do not claim physical death receipts debit aggregate casualties.

The private receipt adapter and activation crash marker are intentionally not fabricated here; they require the new source receipt and further focused review before promotion. The played Pillager fixture cannot be substituted.
